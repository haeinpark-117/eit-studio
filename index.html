Whisper large-v3-turbo transcribes every recording in the browser, so nobody types out what the participants said. Any transcription can still be corrected by hand before it is scored.

Every item scored automatically

Each transcription is aligned against your target word by word, and word error rate (WER) and accuracy are calculated for you. The normalization rules behind them stay visible, editable, and exported with the results.

›Administering the task in the browser

The administration tool delivers a sentence set on the schedule specified in the original design: the stimulus plays, a fixed silent pause of 2.5 s follows, a ring tone marks the end of the pause, and the response window opens. The window is not the same for every item — it is the stimulus articulation time plus 2 s, plus a further 0.5 s for each syllable beyond seven, so that longer sentences are given proportionally more time (Ortega et al., 2002; Wu et al., 2022).

Every boundary is placed on the browser's audio clock rather than on page timers, so the schedule does not drift over a session. Each response is written to storage as it is recorded, which means an interruption costs one item rather than all of them, and the session ends with one audio file per item plus a log of the schedule actually used — exactly what the scoring tool expects, with no segmentation step and no target list to enter a second time.

Two checks run before a participant is seated: a real test recording that is played back and listened to, and a test write to browser storage that catches a private window or a blocked database. Neither failure is recoverable once a session is under way.

›Splitting one long recording into items

If a whole session sits in a single file, the segmentation tool writes it out as one file per item, ready to drop straight into scoring. Boundaries can be placed in three ways, and which one to use depends on what the recording contains.

Recordings usually open with the researcher's spoken instructions. Find task start locates the point where the regularly spaced run of responses begins, and everything before it is ignored; Fit to expected count adjusts the silence threshold until the number of segments matches the number of items you declared.

Nothing is exported until you have seen it. The waveform shows every boundary in place, each segment can be played by clicking its row, boundaries can be dragged, added, or deleted, and each row carries a confidence level with a note when something looks wrong — a segment that is very short, one that appears clipped, or spacing that departs from the rest of the run.

›Reading the output table — column by column

One row per recording. Rows can be sorted by participant and item, by lowest accuracy, or by lowest confidence; the last two are the fastest way into the items that need checking.

Self-corrections

By default the transcription is scored as produced, so a false start is aligned as an insertion and counts against the score. The scoring-rules panel offers an alternative: where a stretch of words is restarted, the first attempt is removed and only the repair is scored, following the convention that a self-corrected response is credited on its final attempt. The rule is applied to the transcription only, never to the target sentence, and a stretch that also occurs in the target sentence is never removed. Whichever setting is used is recorded in both exports, and the removed words are listed item by item, so the decision remains reportable. Because no heuristic distinguishes a self-correction from a genuine repetition in every case, items scored under this rule warrant review.

Because normalization is applied to both strings before comparison, capitalization, punctuation, and whichever variants you configured never affect the score. A response that is correct but differently punctuated scores as a match; a response that substitutes a grammatical morpheme does not.

›What the numbers do and do not license

Accuracy has a floor

Word error rate is truncated at 1.0, following the standard definition. A response with more errors than there are target words therefore scores 0 % rather than a negative value, so very disfluent responses are not distinguished from silent ones by the score alone.

Confidence is not a probability of being correct

Confidence is internal to the model: the mean probability assigned to the tokens it chose. It is comparable across items processed in the same session with the same model and decoding settings, and not comparable across checkpoints or decoding strategies. A high figure means the model was not hesitating, which is not the same as being right.

The combination is what is informative. Low accuracy with high confidence usually means the participant really did produce something different from the target. Low accuracy with low confidence more often points to the recording — background noise, a clipped onset, a boundary in the wrong place. Those are the rows to open the audio on.

An empty transcription is ambiguous

An item with no recognized speech is scored WER 1.0 and 0 % accuracy. That is correct if the participant said nothing, and wrong if a segment boundary was misplaced. Inspect these directly rather than reading them as non-responses.

Automatic scores still need a human subsample

Whisper transcribes toward an intended reading and can normalize morphosyntactic detail toward more expected forms — precisely the deviations an elicited imitation task measures. The speech recognition page sets out the evidence, and the citation page gives a methods-section template that includes reporting the agreement with a human-verified subsample.

›Checking efficiently, and what the exports contain

The table is built for triage rather than for reading every row. Sort by lowest accuracy to see where the transcription and the target diverge most, and by lowest confidence to see where the model itself was least certain; the two orderings surface different problems. Play the audio for any row you are unsure about.

Export to JSON when you intend to correct by hand: each item carries a transcription_corrected field, a flag field, and a reviewed marker, so a corrected transcription is recorded alongside the automatic one rather than replacing it.

CSV

participant, item, target, whisper, wer, accuracy_pct, confidence, avg_logprob, duration_s, file, model, rules, self_corrections_removed

JSON

The same item-level fields, plus the alignment operations under ops, the string the score was computed on under transcription_scored, and a meta block recording the Whisper model, the decoding description, how confidence was computed, the full scoring-rule configuration, the number of target items, and a timestamp.

Privacy by architecture

Participant audio never
leaves the computer.

Speech recognition runs inside the browser itself. There is no server to send recordings to, because there is no server.

No upload, no account

Nothing to sign up for and nothing transmitted. Open the page and work — there is no account to create and no usage limit to reach.

Runs on your GPU

Whisper large-v3-turbo runs via WebGPU where available, with a WASM fallback. The model is downloaded once (about 1.5 GB) and cached, after which a 30-item set takes roughly five to ten minutes on a recent laptop.

Easier ethics approval

Because identifiable speech data stay on the researcher's own machine, no third-party processor needs to be declared.
