How it works

A walkthrough,
step by step.

How the task is administered, how a long recording is split into items, and how to read every column of the scored output.

01 Administering the task in the browser Load a sentence set, choose the practice items, check the microphone and storage, and start the session. ›

The administration tool plays your sentence set to the participant, records each answer, and hands the files to the scoring tool. Setting up a session takes four steps, and the participant sees none of them.

1 · Load the sentence set

Two things go in: the recorded stimuli the participant will hear, and the target sentence for each item with its syllable count. The button loads both at once for the 30-item English EIT of Ortega et al. (2002), using the stimulus recordings of Park (under 2nd review); otherwise drop in your own files and paste your own targets. The tool checks that the two counts match before it will start.

2 · Choose the practice items

Three practice items come before the scored set so that the participant meets the timing once before it counts. They are provided in English and in Korean; practice answers are recorded but left out of the export.

3 · Check the microphone and the storage

This is the step worth not skipping. Record five seconds, play it back, and listen — a level meter alone will not catch a muted headset microphone or a browser writing silence. The storage check writes and deletes one test record, which is what catches a private browsing window before the participant arrives rather than after.

Where the input cannot be turned up far enough at the desk, a fixed gain of up to +24 dB can be applied on the way in. It is a constant multiplication applied before the file is written, so it raises the noise by exactly as much as the speech: it makes a quiet recording louder, not cleaner, and the input at the interface is still the place to start. The browser's automatic gain control is left off throughout, because it moves during a response and would leave amplitude and duration unreadable. The setting is written into the session log, together with the peak level and any clipped samples for each response, so a level can be read against it afterwards.

4 · Start the session

From here the screen belongs to the participant. A short instruction screen comes first, then the practice items, then a screen naming how many sentences are about to follow.

Each item then runs the same way: the sentence plays, a short pause follows, a ring tone marks the end of the pause, and a bar counts down the time available to answer. Longer sentences are given proportionally longer to answer, following the original design (Ortega et al., 2002; Wu et al., 2022). Items follow one another without a gap, as they do in the source recording: the next sentence is scheduled for the moment the last response window closed, and starts later only by however long the machine needed to write the response away — under a fifth of a second in testing.

When the session ends

Download the ZIP first. It contains one audio file per item, the target list, and a log of the schedule that was actually used, which is what you would report in a methods section. Then send the recordings straight to the scoring tool: the targets and the audio are already there, so nothing has to be uploaded or typed a second time.

If a session is ended early, the answers recorded up to that point can still be downloaded and scored — but the session cannot be resumed.

02 You already have the recordings — one file per item Load your target sentences, set the scoring rules, and drop the audio in. Recordings collected elsewhere are scored no differently. ›

Recordings collected any other way are scored the same as recordings made here. What the scoring tool expects is one audio file per item, each holding a single answer to a single target sentence.

1 · Load the target sentences

Paste them in, upload a file, or load the Ortega et al. (2002) set with the button. An item number at the start of a line is used if it is there, and the items are numbered in the order they appear if it is not. The syllable count is the one thing that cannot be left out: it is the last value on each line, and it is what sets the response window.

2 · Set the scoring rules

These decide how the target sentence and the transcription are normalized before they are compared. Both are always lowercased and stripped of punctuation; what is optional is spelling out numbers, expanding contractions, and whether a self-correction is scored on its final attempt. Spelling out numbers covers clock times, which one transcript may write as 11:30 and another as 1130, 11:30pm or in words: all of them reduce to the same words, so a response is not penalized for how the time was typed. Whatever is chosen here is written into both exports, so the exact configuration can be deposited with the study materials.

The same panel holds the one judgement the tool makes on its own. Given audio that contains no speech, Whisper does not return nothing — it returns a stock phrase from the subtitle tracks it was trained on, most often Thank you. or you, so a recording holding only a cough or a bump against the microphone comes back looking like an attempt. Where the whole output is one of the listed phrases and its confidence is below the threshold, the item is scored as no response. The match is on the whole output and never on a phrase inside a longer one, the list and the threshold are yours to set, and a correction or a review of the item overrides the filter. Nothing is discarded: the original output stays in the table and in transcription_raw, the affected rows are marked in the export, and the results panel reports how many items were filtered. Listen to those items before reporting them.

3 · Drop in the recordings

Files named participantID_itemNN are matched to items automatically; anything named otherwise can be assigned by hand in the table underneath. The audio is read in the browser and never uploaded.

03 You already have the recordings — one long file per participant Split a continuous session into one file per item first. Boundaries can be placed in three ways, and they are not equally accurate. ›

If a whole session sits in a single file, the segmentation tool writes it out as one file per item, ready to drop straight into scoring. Boundaries can be placed in three ways, and they are not equally accurate.

1 · Timing grid + stimulus audio The most accurate. Each stimulus is measured from the audio itself, so the window for every item is placed from the schedule rather than estimated. Items the participant left silent still receive a window, and are marked as such.
2 · Timing grid, sentence set only The same placement, except that stimulus length is estimated from syllable counts rather than measured. Use it when the stimulus files are not to hand.
3 · Silence detection The least accurate, and a fallback. Boundaries are placed wherever the recording falls silent, which cannot distinguish a skipped item from a pause: one silent item shifts every item number after it. Use it only when the schedule is unknown.

The remaining controls belong to silence detection. A recording may open with the researcher's spoken instructions: Find task start locates the point where the regularly spaced run of responses begins, and everything before it is ignored. Max. response sets how long a single answer can plausibly be — a stretch of speech longer than this is not treated as a response at all, which is what removes most instruction speech. Fit to expected count then adjusts the silence threshold until the number of segments matches the number of items you declared.

The waveform then shows every boundary in place. Each segment can be played by clicking its row, boundaries can be dragged, added, or deleted, and each row carries a confidence level with a note when something looks wrong — a segment that is very short, one that appears clipped, or spacing that departs from the rest of the run.

04 Reading the output table One row per recording, and what every column holds — accuracy, word error rate, and the confidence figure. ›

One row per recording. Rows can be sorted by participant and item, by lowest accuracy, or by lowest confidence; the last two are the fastest way into the items that need checking.

What each column holds

ParticipantRead from the file name when it follows participantID_itemNN; otherwise whatever you assigned by hand in the file table.
ItemThe item number, which is what links the recording to a target sentence.
TargetYour target sentence after normalization — lowercased, punctuation stripped, scoring rules applied. This is the string the comparison actually uses, not the string you pasted in.
WhisperThe transcription after the same normalization, with the alignment against the target marked. Hovering a marked word shows what it was aligned to.
Accuracy100 × (1 − WER), in percent.
WERWord error rate: (S + D + I) / N over a word-level minimum-edit alignment, where N is the number of words in the normalized target. Truncated at 1.0.
ConfidenceThe mean probability of the tokens the model selected, shown as a percentage with the raw mean log probability beneath it.
AudioPlays that recording, so a questionable item can be checked without leaving the table.

How the alignment is marked

The three edit types that enter the word error rate are marked in the transcription itself, so a score can be traced to the words that produced it.

white Substitution. A word produced in place of a target word. Hover to see the target word it replaced.
of Insertion. A word in the transcription with no counterpart in the target.
▲ Omission. A target word with no counterpart in the transcription. Hover to see which word is missing.
unmarkedA match, which contributes nothing to the error rate.
the boy was Self-correction, if that rule is enabled. A restarted stretch that was excluded from the comparison. It contributes nothing to the error rate, and is shown so that the exclusion remains visible.
Target (7 words)
the streets in this city are wide
Whisper
the streets in the city are white

Two substitutions, no insertions, no omissions, over seven target words: WER = 2 / 7 = .286, accuracy = 71.4 %.

Normalization is applied to both strings before the comparison, so capitalization, punctuation, and whichever variants you configured never affect the score. A response that is correct but differently punctuated scores as a match; one that substitutes a grammatical morpheme does not. Where the self-correction rule is enabled, a restarted stretch is removed from the transcription only — never from the target, and never when it also occurs in the target — so that the response is credited on its final attempt. The setting used and the removed words are recorded in both output files, and since no heuristic distinguishes a self-correction from a genuine repetition in every case, items scored under this rule warrant review.

What the numbers do and do not license

Accuracy has a floor. Word error rate is truncated at 1.0, so a response with more errors than there are target words scores 0 % rather than a negative value; very disfluent responses are therefore not distinguished from silent ones by the score alone.

Confidence is not a probability of being correct. It is internal to the model: the mean probability assigned to the tokens it chose, comparable across items processed in the same session with the same model and decoding settings, and not comparable across checkpoints or decoding strategies. The combination is what is informative. Low accuracy with high confidence usually indicates that the participant produced something different from the target; low accuracy with low confidence more often points to the recording — background noise, a clipped onset, a boundary in the wrong place. Those are the rows to open the audio on.

An empty transcription is ambiguous. An item with no recognized speech is scored WER 1.0 and 0 % accuracy, which is correct if the participant said nothing and wrong if a segment boundary was misplaced. Inspect these directly rather than reading them as non-responses.

Automatic scores still need a human subsample. Whisper transcribes toward an intended reading and can normalize morphosyntactic detail toward more expected forms — precisely the deviations an elicited imitation task measures. The speech recognition page sets out the evidence, and the citation page gives a methods-section template that includes reporting the agreement with a human-verified subsample.

Correcting a transcription

Any row opens on a click. The panel that appears shows the target sentence, what the model produced, and an editable copy of that transcription, together with the recording, so a questionable item can be heard and corrected without leaving the table. The word error rate that would follow from the edit is shown as it is typed.

A correction does not replace the automatic transcription. It is stored as a second field: transcription_raw holds what the model produced, transcription_final what the item was scored on, and reviewed records that a person examined the item, whether or not anything was changed. Both word error rates are exported — wer_raw and wer_final — so the agreement between automatic and hand-verified scoring can be computed from the export itself rather than reconstructed afterward.

Corrections are kept in the browser and are reapplied when the same recordings are scored again, so a review interrupted partway through can be resumed. They are matched by file name and are restored only where the target sentence is unchanged, which prevents a similarly named file from another study from inheriting an earlier correction. A note above the results reports how many items were carried over, and offers to discard them. Nothing is transmitted: the corrections are held in the browser alongside the recordings, and clearing the browser data removes them.

05 Exporting the results CSV when the scores go straight into analysis, JSON when the alignment and the settings have to travel with them. ›

Two formats are offered above the table. Both carry the automatic transcription and any correction made to it, so the export records what was scored and what the model originally produced. Use the CSV where the scores go directly into analysis, and the JSON where the alignment, the decoding settings, and the scoring configuration have to travel with them.

CSV

participant, item, target, transcription_raw, transcription_final, reviewed, wer_raw, wer_final, accuracy_pct, confidence, avg_logprob, duration_s, file, model, rules, self_corrections_removed

JSON

The same item-level fields, plus the alignment operations under ops, the string the score was computed on under transcription_scored, and a meta block recording the Whisper model, the decoding description, how confidence was computed, the full scoring-rule configuration, the number of target items, how many of them were reviewed and corrected, and a timestamp.
